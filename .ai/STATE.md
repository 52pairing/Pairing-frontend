## 주의사항

- 응답 카드 필드는 확정 계약(`projectTitle`, `counterpartName`, `clientBusinessField`, 금액·기간·생성일·근무 방식·상태)을 사용합니다.
- 서버가 `id DESC`로 정렬하므로 프론트에서 재정렬하지 않습니다.
- `DRAFT`는 서버 정책에 따라 `ALL` 탭에서만 내려오는 것으로 처리하며 상세 이동을 비활성화합니다.
- 실제 네트워크 성공·오류 응답은 아직 미검증입니다.
- `npm run lint`: 오류 없이 통과, 기존 `coverage/lcov-report/block-navigation.js`의 미사용 eslint-disable 경고 1건 유지
- `npm run test -- --runInBand`: 4 suites, 21 tests 통과
- `npm run build`: 통과
- 브라우저 및 실제 API 검증: 테스트 인증 세션이 없어 미실행
- 실제 화면의 스택 위치로 일부 계약에서 `createdAt`이 `undefined`인 응답을 확인해 생성일 누락값을 `-`로 안전 처리했습니다. 백엔드의 `createdAt` nullable 정책은 추가 확인이 필요합니다.
- 착수금 결제 버튼은 카드의 `payableSettlementId`로 정산 상세를 조회하고, 결제 API 성공 응답을 별도 재조회 없이 완료 화면에 표시하도록 연결했습니다.
- 결제 완료 후에는 진행 중 탭 대신 해당 계약 상세로 이동합니다.
- 착수금 버튼 노출은 `SIGNED && !depositPaid` 기준으로 유지하고, `payableSettlementId`가 누락돼도 목업 결제로 진행하지 않습니다.
- 실제 목록 응답에서 `payableSettlementId` 누락이 확인되어, 해당 프로젝트의 정산 목록에서 결제 가능한 `DEPOSIT` 건을 찾아 결제 상세로 이어지는 보완 경로를 추가했습니다.
- 계약 상세가 `SIGNED`만 체결 완료로 판단하던 오류를 수정해 `IN_PROGRESS`, `COMPLETION_PENDING`, `COMPLETED`, `TERMINATED`도 서명·계약 체결 완료로 표시합니다.
- 계약 상세 화면을 `GET /contracts/{contractId}` 단일 응답 기반으로 정리하고 직무·근무 조건 메타 추가 호출을 제거했습니다. 상태 뱃지, 양측 서명, 계약 확정, 계약 조건, 조항, 특약사항을 확정 필드 계약에 맞췄습니다.
- 전자서명 최종 제출 전에 되돌릴 수 없음을 안내하는 확인 모달을 추가하고, 요청 중 모달·제출 버튼을 잠가 `ALREADY_SIGNED` 중복 요청을 방지했습니다.
- 서명 미리보기 화면도 계약 상세 단일 API만 사용하도록 직무 메타 추가 호출을 제거했습니다.
- 서명 완료 모달은 서명 API 응답을 직접 사용하고, 급여를 `payUnit + payAmount`로 표시하며 `MONTHLY`에서 월별 지급 문구를 파생합니다.
- 서명 화면의 계약 본문을 서버 PDF Blob iframe으로 교체해 주요 업무, 계약 금액, 근무 장소, 조항 번호와 서명란을 서버 출력과 동일하게 유지합니다. 계약서 수정 버튼과 대금 분할 UI는 두지 않습니다.
- iframe PDF 미리보기에서 브라우저 툴바·썸네일 패널·스크롤 UI를 숨기고 문서 폭 맞춤으로 표시하도록 뷰어 옵션을 적용했습니다.
- 성공보수 결제 모달을 목업에서 정산 상세·카드 목록·결제 API 흐름으로 교체했습니다. 서버 요율·금액을 사용하고 목록 기간으로 개월 수를 계산하며 기본 카드를 표시합니다.
- 성공보수 결제 완료 화면은 프로젝트 정산 목록을 한 번 조회해 착수·성공보수 수수료와 결제일, 전체 수수료를 표시하며 최종 종료일을 제거했습니다.
- 계약 액션에서 `signatureRequired`를 상태 없이 우선 적용하던 오류를 수정해, 서명은 `SIGN_PENDING`에서만 표시하고 `COMPLETION_PENDING`은 성공보수 결제로 분기합니다.
