# Security Guide

프로젝트에서 민감 정보와 사용자 개인정보를 안전하게 처리하기 위한 규칙입니다.

AI 도구와 모든 작업자가 동일하게 지켜야 합니다.

## 1. 저장소에 커밋하면 안 되는 정보

다음 정보는 저장소에 commit 또는 push하지 않습니다.

- `.env`
- `.env.local`
- `.env.development`
- `.env.production`
- Access token
- Refresh token
- 인증 쿠키
- 세션 값
- API key
- Secret
- 비밀번호
- 인증서
- Private key
- 실제 사용자 개인정보
- 테스트 계정의 실제 아이디와 비밀번호
- 내부 전용 URL 또는 비공개 서버 주소

민감 정보가 커밋 이력에 포함됐다면 파일을 삭제하는 것만으로 해결되지 않습니다.

즉시 팀에 알리고 해당 토큰, 비밀번호, 키를 폐기하거나 재발급합니다.

## 2. 문서 작성 규칙

Markdown 문서에도 실제 secret 값을 작성하지 않습니다.

환경변수는 다음 두 가지만 기록합니다.

- 환경변수 이름
- 환경변수 용도

예시:

```text
NEXT_PUBLIC_API_URL: 백엔드 API 기본 주소
```

잘못된 예시:

```text
NEXT_PUBLIC_API_URL=https://실제-내부-주소
```

## 3. 환경변수

실제 사용하는 환경변수는 프로젝트 설정이 확정될 때 추가합니다.

### 클라이언트에 노출 가능한 변수

`NEXT_PUBLIC_` 접두사가 붙은 값은 브라우저 번들에 포함됩니다.

비밀번호, secret, private key, 서버 전용 토큰에는 절대 사용하지 않습니다.

| 이름 | 용도 | 실제 값 커밋 |
| --- | --- | --- |
| `NEXT_PUBLIC_API_URL` | 백엔드 API 기본 주소 | 금지 |
| `NEXT_PUBLIC_SITE_URL` | 프론트 서비스 주소 | 금지 |

소셜 로그인, 결제, 외부 서비스 등을 실제로 도입하면 사용 중인 변수만 이 표에 추가합니다.

### 서버 전용 변수

서버 전용 secret에는 `NEXT_PUBLIC_` 접두사를 사용하지 않습니다.

서버 코드에서만 접근해야 합니다.

## 4. 인증 정보 처리

* 인증 처리는 프로젝트의 공통 인증 로직을 사용합니다.
* 컴포넌트에서 Access token이나 Refresh token을 직접 다루지 않습니다.
* 인증 토큰을 `console.log`로 출력하지 않습니다.
* 인증 쿠키 값을 화면, 문서, Issue, PR에 작성하지 않습니다.
* 401 또는 세션 만료 처리는 공통 처리 방식을 따릅니다.
* 로그인 상태를 확인하기 위해 민감한 인증 값을 클라이언트 코드에 노출하지 않습니다.

## 5. 개인정보 처리

이 프로젝트는 다음과 같은 개인정보를 다룰 수 있습니다.

### 공통

* 이름
* 이메일
* 휴대폰 번호
* 생년월일
* 주소
* 프로필 이미지

### 클라이언트

* 기업명
* 사업자등록번호
* 담당자 정보
* 업무용 이메일
* 결제 또는 정산 정보

### 프리랜서

* 이력서
* 경력
* 학력
* 포트폴리오
* 프로젝트 경험
* 자격증
* 계좌 또는 정산 정보

다음 규칙을 지킵니다.

* 실제 개인정보를 테스트 데이터로 커밋하지 않습니다.
* 화면 캡처를 공유할 때 개인정보를 가립니다.
* 로그에 개인정보 전체를 출력하지 않습니다.
* API 에러 로그에 요청 body 전체를 그대로 출력하지 않습니다.
* 테스트 데이터는 명확한 가상 정보만 사용합니다.
* 주민등록번호 등 서비스에 필요하지 않은 민감 정보는 수집하지 않습니다.
* 사업자등록번호, 전화번호, 계좌번호는 필요한 화면에서만 표시합니다.
* 화면 표시 시 필요한 경우 일부 값을 마스킹합니다.

## 6. 파일 업로드

이력서와 포트폴리오 파일을 업로드할 때 다음을 확인합니다.

* 허용 확장자
* MIME type
* 최대 파일 크기
* 파일명 처리
* 악성 파일 검사 여부
* 다운로드 권한
* 비공개 파일 접근 권한
* 파일 URL 만료 또는 접근 제어

프론트 검증만으로 파일 보안을 보장하지 않습니다.

백엔드에서도 동일한 검증이 필요합니다.

## 7. AI 및 외부 서비스 연동

AI 매칭, A2A 협상, 온디바이스 기능 또는 외부 AI API를 사용할 때 다음을 확인합니다.

* 어떤 사용자 데이터가 AI에 전달되는지
* 원본 이력서나 개인정보가 외부 서버로 전송되는지
* 사용자 동의가 필요한지
* 개인정보를 제거하거나 마스킹할 수 있는지
* 응답 데이터가 저장되는지
* 로그 또는 학습 데이터로 사용되는지
* 데이터 보관 기간이 있는지

개인정보가 포함된 원문을 필요 이상으로 AI 서비스에 전달하지 않습니다.

온디바이스에서 처리할 수 있는 데이터는 서버 전송 필요성을 먼저 검토합니다.

## 8. 브라우저 저장소

localStorage와 sessionStorage에 다음 정보를 저장하지 않습니다.

* 비밀번호
* Access token
* Refresh token
* 계좌번호 전체
* 카드번호 전체
* 인증번호
* 민감한 개인정보 원문

작성 중인 폼을 임시 저장해야 한다면 저장 범위와 만료 시점을 명확히 정합니다.

민감 정보는 제외하거나 최소한으로 저장합니다.

## 9. 로그 및 오류 보고

* 운영 환경에서 민감한 디버그 로그를 남기지 않습니다.
* API 요청 body 전체를 무조건 출력하지 않습니다.
* 토큰, 쿠키, 비밀번호, 인증번호는 로그에서 제거합니다.
* 사용자에게 내부 서버 구조나 stack trace를 그대로 노출하지 않습니다.
* Issue와 PR에 에러 화면을 첨부할 때 개인정보를 가립니다.

## 10. Git 확인

commit 전에 확인합니다.

```bash
git status
git diff --cached
```

다음 항목이 포함됐는지 확인합니다.

* `.env` 파일
* 실제 API key
* 테스트 계정 정보
* 내부 URL
* 개인정보
* 토큰 또는 쿠키
* 디버깅용 로그

## 11. 보안 문제 발견 시

1. 추가 commit과 공유를 중단합니다.
2. 팀에 즉시 알립니다.
3. 노출된 secret을 폐기하거나 재발급합니다.
4. 필요한 경우 Git 이력 제거 방법을 논의합니다.
5. 원인과 재발 방지 방법을 정리합니다.
