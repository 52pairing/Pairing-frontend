# Testing Guide

변경 후 어떤 검증을 실행해야 하는지 정리합니다.

모든 변경에 모든 테스트를 강제로 실행하지 않습니다.
변경 범위와 영향도에 맞는 검증을 선택합니다.

실제 명령어는 현재 프로젝트의 `package.json`을 기준으로 합니다.

## 1. 명령어 확인

테스트 또는 검증을 실행하기 전에 `package.json`의 `scripts`를 확인합니다.

### 현재 실제로 존재하는 스크립트

```bash
npm run dev      # next dev (개발 서버)
npm run build    # next build
npm run start    # next start (프로덕션 서버)
npm run lint     # eslint
```

### 아직 존재하지 않는 스크립트 (확인 필요)

현재 `package.json`에는 테스트 스크립트와 테스트 도구가 없습니다.

- `npm run test` — 미설치
- `npm run test:unit` — 미설치
- `npm run test:e2e` — 미설치
- Jest — 미설치
- Playwright — 미설치

> README에는 Jest·Playwright 사용이 명시돼 있으나 실제 `package.json`에는 아직 도입돼 있지 않습니다. 테스트 도구가 실제로 추가되면 이 문서를 실제 스크립트 기준으로 갱신합니다.

실제로 존재하지 않는 명령은 실행하거나 문서에 통과했다고 기록하지 않습니다.

## 2. 기본 검증

### 개발 서버

```bash
npm run dev
```

확인 항목:

* 페이지가 정상적으로 렌더링되는지
* 콘솔에 신규 오류가 없는지
* 주요 사용자 동작이 정상인지
* 반응형 레이아웃이 깨지지 않는지

### lint

```bash
npm run lint
```

확인 항목:

* 신규 lint 오류
* 신규 warning
* 사용하지 않는 import와 변수
* React Hook 의존성 오류

### build

```bash
npm run build
```

확인 항목:

* TypeScript 오류
* Next.js 빌드 오류
* 서버·클라이언트 컴포넌트 경계 오류
* 동적 라우트 오류
* 환경변수 누락
* 정적 생성 오류

## 3. 변경 유형별 검증

아래 표에서 단위 테스트·E2E 테스트 항목은 테스트 도구가 도입된 이후에 적용합니다. 현재는 `lint`와 `build`, 브라우저 확인을 기본 검증으로 사용합니다.

| 변경 유형 | 기본 검증 |
| --- | --- |
| 문서만 변경 | 링크, 경로, 오탈자, 민감 정보 확인 |
| Tailwind 또는 문구 변경 | lint + 브라우저 화면 확인 |
| 공통 UI 컴포넌트 변경 | lint + 관련 화면 전체 확인 |
| 컴포넌트 상태·이벤트 변경 | lint + 브라우저 동작 확인 (+ 단위 테스트: 도입 후) |
| 커스텀 훅 변경 | lint + 사용하는 화면 확인 (+ 단위 테스트: 도입 후) |
| API 연동 변경 | lint + 실제 요청·응답 확인 + 에러 처리 확인 |
| 인증 변경 | lint + 로그인·로그아웃·401·세션 만료 확인 |
| 라우팅 변경 | lint + build + 직접 URL 접근 확인 |
| 폼 검증 변경 | 정상값·경계값·오류값·중복 제출 확인 |
| 파일 업로드 변경 | 확장자·용량·실패·재시도 확인 |
| 실시간 기능 변경 | 연결·재연결·중복 수신·구독 해제 확인 |
| 공통 설정 변경 | lint + build |
| 배포 전 또는 큰 변경 | lint + build + (관련 test: 도입 후) + 주요 흐름 확인 |

## 4. API 연동 검증

API를 연동하거나 변경했다면 다음을 확인합니다.

### 정상 응답

* 요청 URL
* HTTP method
* Path parameter
* Query parameter
* Request body
* 인증 정보 전달
* 실제 응답 필드
* nullable 필드
* 배열과 단일 객체 구분

### 실패 응답

* 400
* 401
* 403
* 404
* 409
* 500
* 네트워크 오류
* timeout

### 화면 처리

* 로딩 상태
* 성공 상태
* 빈 상태
* 실패 상태
* 재시도
* 버튼 중복 클릭 방지
* 오류 발생 후 입력값 유지

실제 API를 확인하지 못했다면 `.ai/STATE.md`와 PR에 `미검증`으로 기록합니다.

## 5. 폼 검증

폼 작업 시 다음을 확인합니다.

* 필수값 누락
* 최소 길이
* 최대 길이
* 경계값
* 잘못된 형식
* 서버 중복 검사
* 비밀번호 일치
* 제출 중 중복 클릭
* 서버 에러 발생 후 입력값 유지
* 새로고침 또는 페이지 이동 시 임시 저장 정책
* 모바일 키보드와 입력 타입

## 6. 반응형 확인

최소한 다음 화면 크기를 확인합니다.

* 모바일
* 태블릿
* 데스크톱

확인 항목:

* 가로 스크롤 발생 여부
* 버튼과 입력창 잘림
* 모달 크기
* 긴 텍스트
* 테이블 또는 카드 레이아웃
* 고정 헤더와 하단 버튼
* 터치 영역 크기

## 7. 접근성 확인

* 키보드로 주요 기능 사용 가능
* focus 표시
* input과 label 연결
* 버튼의 접근 가능한 이름
* 모달 닫기
* disabled 상태 전달
* 오류 메시지와 입력 필드 연결
* 이미지 대체 텍스트

## 8. 검증 결과 기록

검증 결과는 다음 파일에 기록합니다.

* 진행 중 작업: `.ai/STATE.md`
* 인수인계: `.ai/HANDOFF.md`
* 완료 기록: `.ai/WORKLOG.md`
* Pull Request 본문

예시:

```text
- npm run lint: 통과
- npm run build: 미실행 — 문서만 변경
- 브라우저 확인: 통과
- 실제 API 성공 응답 확인: 미실행 — 백엔드 배포 대기
```

## 9. 실패한 검증

검증이 실패하면 숨기지 않습니다.

다음 내용을 함께 기록합니다.

* 실행한 명령어
* 오류 메시지
* 이번 변경으로 발생한 오류인지
* 기존 오류인지
* 해결 여부
* 남은 영향

기존 오류라고 판단하더라도 근거 없이 무시하지 않습니다.

## 10. 실행하지 못한 검증

환경이나 권한 문제로 실행하지 못했다면 `미실행`으로 작성합니다.

예시:

* 로그인 테스트 계정 없음
* 백엔드 미배포
* 관리자 권한 없음
* 외부 서비스 테스트 키 없음
* CI 환경에서만 실행 가능
* 테스트 스크립트 미설치

실행하지 않은 검증을 통과로 기록하지 않습니다.
